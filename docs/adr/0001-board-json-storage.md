# ADR-0001 看板存储换成 board.json（可变卡 + 只追加证据）

- 状态：已接受（2026-11-18）

## 背景

旧看板是 append-only 的 board.jsonl：一行一条记录，写出去就不能改，并发靠 expectedSeq + sha256 去重兜。它适合「证据流」，但不适合「状态」。
用户明确要求看板是项目核心、卡片要带状态与优先级，而状态天然要**被改**。继续用 append-only 就要靠事件回放算状态，读时归并，语义与实现都开始绕。

## 决策

board.json 单文件，结构 { cards, records }：cards 可变（带 rev），records 只追加并以 cardId 外键挂卡。并发用进程内 mutex 串行 + rev CAS，落盘走临时文件 + 原子 rename。

## 后果

正面：状态直读，无需回放；审计仍在（每次状态变更追加一条 card_status）；卡与证据职责清晰。
负面：整板重写（条目上限内可接受）；进程外第二个写者需要靠 rev 冲突暴露而不是被挡住；必须做一次迁移（见 T10）。
被放弃的方案：每卡一文件（列板要读目录、跨卡排序自己拼）；纯事件 + 读时归并（「记录直接带 status」只在视图上成立）。
